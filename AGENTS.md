# Lantern Depths project instructions

- Keep the original puzzle engine authoritative. Do not replace it with AI-improvised story logic.
- Preserve upstream attribution, source pinning, executable checksums and third-party licences.
- Do not claim the executable was freshly compiled until a reproducible source build exists.
- Invisible objects must not appear in the UI before discovery. Test closed-container visibility and darkness.
- Read project docs and current code before expanding the adaptation.
- Keep save compatibility explicit; each engine must own an independent story-byte copy.
- Use generated raster artwork for game paintings; record prompts and provenance, and integrate actual files into `public/art`.
- Distinguish a static environment plate from state-correct object artwork.
- Run `npm test`, `npm run test:browser` and `npm run build` for gameplay or rendering changes.
- Do not add paid runtime services, credentials, private workspace files or unrelated personal information.

- Follow `docs/ROADMAP.md` as the accepted product goal; record completed increments and remaining limitations. Finish authored connected regions before platform generalisation.
